# Notemap

Персональная карта с заметками, фото, оценками и коллекциями. React, TypeScript, MapLibre и Geoapify; данные хранятся на устройстве в IndexedDB. Сервер для обычной работы не нужен.

Тестовая PWA: [sumergeg.github.io/notemap](https://sumergeg.github.io/notemap/). На Android открыть в Chrome → меню → «Установить приложение» или «Добавить на главный экран». Данные с localhost переносить через полный архив; автоматически они не появляются.

## Запуск

Node.js 22.12+. Выполнить `npm ci`, создать `.env.local` по `.env.example` с бесплатным browser key Geoapify, затем `npm run dev`. Browser key виден пользователю; серверные секреты здесь не использовать.

`npm test` проверяет логику; `npm run build` создаёт статическую PWA в `dist`. Для project Pages задать `NOTEMAP_BASE_PATH=/notemap/`. Каждый push в `main` автоматически запускает `.github/workflows/pages.yml`: тесты → сборка → публикация Pages. При ошибке сайт не обновляется. Публичный ключ задаётся Actions variable `VITE_GEOAPIFY_API_KEY`. Сохраняется ручной запуск: `publish=false` готовит только артефакт, `publish=true` также публикует.

## Обновление установленной PWA

По решению пользователя от 15.10.2026 поиск организаций рядом отключён. Личные места добавляются через «+» или нажатием на карту: выбрать точку, задать название и сохранить заметку. Геопозиция остаётся отдельным действием для ориентирования. Поиск по названию/адресу доступен в верхней строке.

Кнопка «Где я?» включает синюю точку текущей геопозиции и обновление через GPS. Повторное нажатие выключает слежение. Переход к точке — отдельное действие; поиск и ручное добавление доступны без GPS. Слежение приостанавливается в фоне и не включается автоматически после перезапуска приложения. Координаты не сохраняются в IndexedDB или логах; точность определяется телефоном, а ореол служит приблизительным визуальным ориентиром.

Профиль → «Проверить обновления» → «Обновить приложение». Перед обновлением сохранить открытый редактор; сохранённые данные IndexedDB остаются. Переустанавливать PWA и очищать данные сайта не нужно. Android может показывать «This app is already installed» в меню браузера: это означает, что приложение установлено; открыть его можно верхним пунктом этого меню или существующим значком.

Оболочка проверяется через сеть с таймаутом 4 секунды и возвращается из кеша без интернета. Новая версия worker активируется по явной команде; кеш предыдущей версии сохраняется для старых вкладок. При ошибке загрузки JavaScript или запуска React вместо пустого экрана доступна кнопка повтора; она не удаляет локальные данные.

## Данные и обмен

Каждый браузер/origin имеет отдельную базу. Профиль позволяет скачать полный архив с фото и восстановить его с подтверждением замены. Очистка данных сайта может удалить записи; регулярно сохраняйте архив. Заметки и коллекции передаются файлами: preview → независимый импорт; новый файл → diff → ручное подтверждение. Автоматической синхронизации, срока действия и отзыва файла нет.

Основная подложка загружается из Яндекс Tiles API, поиск — из Geoapify через интернет. PWA кеширует оболочку приложения; полная офлайн-карта не предусмотрена. Четыре категории и целочисленные оценки 1–10 сохраняются. Основная карта использует русские подписи, сферическую проекцию и тайлы 2× на экранах высокой плотности; saveData и восстановление выбирают обычные тайлы. Логотип Яндекса и переход в Карты видны поверх карты. Мини-карты и preview коллекций пока используют Geoapify.

Подложка по умолчанию — `osm-bright-smooth`. Тайлы `@2x` используются на экранах высокой плотности только при известном быстром соединении; неизвестная сеть (в том числе Safari без Network Information API), медленная сеть и экономия трафика получают обычные тайлы. Плотность холста ограничена 2. Мини-карты используют тот же выбор качества и ленивую загрузку.

При ошибке запуска или отсутствии результата за 8 секунд карта один раз переходит на обычные растровые тайлы и плотность холста 1, сохраняя текущую область. Если ещё через 12 секунд результата нет, доступен ручной повтор; поздняя загрузка снимает ошибку. Возвращение сети после ошибки автоматически повторяет запуск. Постоянных повторов и polling нет; недоступность самого Geoapify или отсутствие WebGL этим не устраняется.

В профиле доступно сравнение карт (`#map-compare`): Яндекс JS API 3.0 в векторном режиме, Яндекс Tiles API и Geoapify в MapLibre. Для JS API нужен отдельный браузерный ключ `VITE_YANDEX_JS_API_KEY` с HTTP Referer `sumergeg.github.io` и `localhost`; для Pages — одноимённая Actions variable. SDK загружается только при открытии векторного варианта с официального домена; переключение уничтожает прежнюю карту. Кнопки поворота на 45° и возврата на север позволяют сравнить подписи. Ориентацией подписей управляет Яндекс, улицы могут идти вдоль дороги. Показатель готовности вектора не смешивается со временем первого растрового тайла. Личные слои не загружаются, область передаётся только между вариантами на этом экране. Растровые замеры выполняются без Retina и зависят от кеша. Основная карта остаётся на Яндекс Tiles API, поиск — Geoapify. JS SDK требует HTTP Referer: документ отправляет только origin при внешних запросах, поиск Geoapify по-прежнему использует `no-referrer`. Ошибка необязательного SDK показывается внутри сравнения и не включает экран общего восстановления PWA.
